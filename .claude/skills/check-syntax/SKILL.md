# check-syntax

Per-file проверка синтаксиса **без браузера** через JavaScriptCore (`osascript -l JavaScript`): каждый файл оборачивается в `new Function(src)` — ровно ручная процедура из CLAUDE.md. Ловит опечатки/незакрытые скобки за доли секунды, до тяжёлого `tests/run.sh`.

## Когда использовать
- Сразу после правки `app.js`, `app-2.js`…`app-5.js`, `data.js` или `telegram-notify.js`.
- Как первый шаг этапа «Automated tests» (см. CLAUDE.md «Процесс разработки фич») — синтаксис, потом `tests/run.sh`.
- Когда нужно быстро понять «вообще парсится?», не запуская полный набор регрессий.

Это **не** замена `tests/run.sh` — проверяет только парсинг, не поведение функций.

## Как запускать

Из любого места (скрипт сам находит корень репо):

```bash
bash .claude/skills/check-syntax/check-syntax.sh
```

- Без аргументов — проверяет все: `app.js app-2.js app-3.js app-4.js app-5.js data.js telegram-notify.js`.
- С аргументами — только перечисленные файлы:

```bash
bash .claude/skills/check-syntax/check-syntax.sh app-2.js telegram-notify.js
```

## Деталь воркера

`telegram-notify.js` использует ES-модульный `export default {…}`, который **нелегален в теле `new Function`**. Скрипт сам заменяет `export default` → `var __d =` во временной копии перед проверкой (исходник не трогается). Это та же замена, что описана в CLAUDE.md.

## Что ожидать
- `✅ <файл>` — парсится; `❌ <файл> — ERR: <сообщение>` — ошибка синтаксиса с текстом из JSC.
- Exit `0` — все файлы ок; exit `1` — есть хотя бы одна ошибка.
- Файл, которого нет на диске, пропускается со строкой `⏭`.

## Ограничения
- `new Function` проверяет **синтаксис**, а не межфайловые ссылки/исполнение — дубли `const` в разных файлах или необъявленные глобалы здесь не всплывут (это ловит `tests/run.sh`).
- Требует macOS `osascript` (JavaScriptCore) — тот же движок, что у тестового раннера.
