# План слияния: прототип «Trade Desk» + аудит + текущий portfolio-dashboard

Статус: **Planning** (2026-09-10). Дополняет `plans/redesign-trading.md` (что строим) ответом на вопрос **как** это встроить в живое приложение без остановки работы. Implementation — отдельными сессиями по §7.

## 1. Принцип: пересадка органов, не пересборка

Приложение продолжает работать всё время слияния. Новые модули подключаются **рядом** со старыми файлами, старые экраны заменяются по одному за флагом, данные и синк не меняют формат до последнего этапа. Три правила:

1. **Один источник правды на каждую сущность.** Сигналы — `signals.js`, график — `chart.js`, позиция — `POS_META`, план сделки — `PLAN_RULES`. Старые движки живут, пока новый не подтверждён теневым сравнением, затем удаляются.
2. **Флаг `desk`.** `localStorage.dash_desk = '1'` (и `?desk=1` в URL) включает новую оболочку; без флага — текущее приложение. Флаг снимается на этапе чистки, когда старые экраны удалены.
3. **Аудит закрывается по ходу, а не отдельным проектом.** Каждая сессия слияния закрывает список находок (§6); quick wins идут первыми, потому что они снижают риск самого слияния (синк, воркер, тесты).

## 3. Что остаётся без изменений

Supabase auth, RBAC (`can`/`canTab`, `supabase-rbac.sql`), формат `ledger_state` (rev, realtime), `PF_TRADES` и налоговый расчёт, семейные портфели и `pf3MyPort`, AI-эндпоинты и промпты воркера (доступ из «Акции» и «Сегодня», не отдельные экраны), cron AI-портфеля, тесты `tests/run.sh` и pre-commit хук с авто-`?v=`, деплой воркера вручную.

## 4. Структура файлов после слияния

```
index.html      data.js → signals.js → chart.js → app.js … app-5.js → desk.js  (+ desk.css за флагом)
signals.js      чистый слой сигналов (из прототипа, с тестами)
chart.js        chartModel (чистая) + renderStockChart (из прототипа, S5)
desk.js         экраны Сегодня / Скринер / Акция / Позиции / Журнал + адаптеры secFromRow, histBars, POS_META
desk.css        токены и компоненты новой оболочки
app*.js         худеют по мере удаления движков и экранов (этап 6)
```

Порядок скриптов важен: `signals.js` до `app.js` (старые функции могут делегировать); `chart.js` — тоже до `app.js` (S5: `boot()` в конце `app-5.js` уже может рисовать карточку, а `chart.js` берёт `RT`/`SIG` только в момент вызова); `desk.js` после `app-5.js` (использует `DATA`, `FX`, `PLAN_RULES`, `RT`). Хук pre-commit проставит `?v=` новым файлам сам.

### 7.1 Итоги S3 (2026-09-10)

Сделано (слой 2, всё аддитивно — старый клиент читает ledger как раньше):
- **Синк:** новые ключи `posMeta`, `desk`, `schemaV` в `snapshotState`/`applyRemoteState`. Снапшот от клиента до S3 (без `posMeta`/`desk`) не затирает локальные данные: они остаются (или берутся из локального бэкапа `dash_bak_*`) и пушатся обратно.
- **Позиция:** `POS_META[tab][TK]={side, stop0, stop, target, riskKr, opened, planId}`; `posMetaNorm/Get/Set/Del`, `posLevelsCheck`, `posCalc` (P&L шорта зеркально, `rNow` от `stop0`, открытый риск до текущего стопа), `bookPositions`, `bookRiskState` (капитал = акции + кэш, риск 1 % на сделку, лимит книги 6 %), `qtyByRisk`, `DESK={riskPct, riskCapPct, shortOk}` + `deskNorm`.
- **План v2:** `planRuleNorm` (поля `side, stop, target, riskKr, status, createdAt`; `done` — источник правды), `planStatus` со стопом/целью/стороной (`hit: level|deadline|stop|target|invalid`; стоп-лосс выхода; «сетап сломан» у входа за стопом; у открытой позиции стоп/цель из `POS_META`), `planRR`, `planMarkOpen`. В старой вкладке «План» — поля «Стоп»/«Цель», действия «Шорт»/«Откупить шорт», R/R, «по риску N шт», кнопка «📍 Открыта», бейджи ⛔/🎯/✖.
- **Бумага:** `secFromRow` (ключ = биржевой символ + валюта) и `deskUniverse` (все разрешённые RBAC v3-вкладки, дедуп, `held` по моим портфелям); гейт свежести `PX_LIVE` — цена live только после живой котировки этой сессии (≤ 30 мин), сид/снапшот не помечается live.
- **Налог шорта:** `pfTaxLots` для сделок `short:true` признаёт результат в дату откупа по средней выручке открытых шорт-продаж (genomsnitt); лонг не изменился.
- **Схема:** `SCHEMA_V=1`, `migrateSchema()`; одноразовые сиды (Anna, Sergei, Gold and Silver, Small Cap, HEM, MU в пустом портфеле) выполняются только при `schemaV < 1` — удалённое больше не воскресает.

Находки аудита: закрыты **goal-gap#2** (стоп/цель на уровне данных и плана; Telegram — S8), **goal-gap#3** (размер по риску), **tests-quality#5**, **tests-quality#10**; частично **goal-gap#1** (сторона в позиции/плане/налоге; открытие шорта из «💸 Сделка» и шорт-вердикты — S4/S6), **data-model-sync#5** и **stale-info#3** (сиды гейтятся `schemaV`; сама цепочка миграций по-прежнему идёт в `init()` — перенос в один `migrateState` и удаление старых шагов — S7).
