## 1. Цель

Приложение отвечает на пять вопросов за один экран каждый: **что купить сегодня · что продать/сократить · что зашортить · где вход/стоп/цель и размер по бумаге X · что с моими позициями**. Для этого:
1. один слой сигналов вместо шести движков;
2. сущность **план сделки** (side, entry, stop, target, R/R, size) как первичный объект;
3. график = свечи + объём + SMA + зоны S/R + линии Вход/Стоп/Цель + маркеры + RSI, с зеркальным режимом шорта;
4. новая IA из 5 экранов вместо 8 виртуальных вкладок + 13 саб-вкладок + карточки из 19 блоков;
5. вычистить устаревшее и дубли.

## 2. Ограничения (не меняются)

## 4. Слой сигналов — `signals.js` (переносится из прототипа)

Чистые функции (без DOM, без глобалов), сигнатуры зафиксированы:

```
indicators(bars)                  → {s50,s100,s200,atr(Wilder 14 по High/Low),rsi(14)}
levelsAt(bars, i, ind)            → {price, res[], sup[], all[]}   // SMA50/100/200, S60/R60 (low/high 60 дн), S20/R20, L52w/H52w, пивоты P/R1/S1/R2/S2; схлопывание ≤0.3% (collapseLevels воркера)
phase(price, day, a50, a100, a200, sup, upTg) → {key,label,rank}   // порт pf3Criterion (app-2.js:256), пороги те же
tradePlan(side, levels, atr, {riskKr, fx, entry}) → {entry, stop, target, rr, riskPct, rewardPct, qty, notionalKr, stopSrc, targetSrc}
snapshot(bars, {riskKr, fx, upTg}) → {price, day, atr, rsi, trendUp, levels, near, phase, long, short, side, verdict, why[], score, markers[]}
markers(bars, ind)                → ретро-сигналы [{i,d,kind:buy|sell|short|cover,price,why}]
```

Правила (единственное место порогов; v2 после судейской панели):
- **Уровни для стопа/цели — только структурные** (без дневных пивотов; пивоты — оверлей).
- Лонг: цель = ближайшее сопротивление ≥ 1.0·ATR и ≤ 2.5·ATR (иначе +2·ATR, флаг `atr-target`, «≈» перед R/R); стоп = ближайшая поддержка ниже минус буфер 0.5·ATR (иначе −1.5·ATR), дистанция стопа не меньше 1·ATR (> 2·ATR — флаг `wide`, подсказка «½ риска»). Шорт — зеркально. *(Калибровка 2026-09-10, `plans/signals-calibration.md` §5–6.)*
- **Вход у уровня, а не по рынку.** У уровня и R/R ≥ 2.0 — по рынку; при R/R 1.2–2.0 — **лимит-цена, при которой R/R = 2.0** на том же стопе и цели: `entry* = (target + 2·stop) / 3`; не у уровня — условный лимит `уровень ± 0.25·ATR` с Δвход %. Лимит «взводится» → уведомление (в приложении — `PLAN_RULES` + Telegram).
- R/R = reward/risk; размер = floor(riskKr / ((entry − stop) × FX)), где riskKr = 1 % капитала выбранного портфеля (настройка `desk.riskPct`), суммарный открытый риск книги ≤ 6 % (`desk.riskCapPct`); «½ риска» (ранний вход без подтверждения тренда) уменьшает qty вдвое, а не только текст.
- Вердикты: `buy` — фаза up/rev/corr/undr, цена у поддержки (≤2 %), R/R ≥ 2.0 по рынку; `short` — SMA50 < SMA200, цена под сопротивлением, R/R ≥ 2.0 (и флаг «шорт доступен», иначе предупреждение); `trim` — >30 % над SMA200 или цена выше таргета (показывается только для бумаг в книге, вне книги — флаг в скринере); `hold` — аптренд без сетапа (с условным лимитом); `wait` — остальное, в т. ч. «ждать уровня» с лимитом. `knife` всегда `wait`.
- Флаги/блокеры: `wide` (стоп > 2·ATR, не блокер), `atr-target` (цель без уровня), `half`, `squeeze` (шорт при day ≥ +4 % или объём ≥ 2× при растущем закрытии — не открывать), `stale-target` (свежий срез ниже среднего FMP > 50 %), `knife`; на этапе 1 добавить `earnings ≤ 3 дн` из `?earnings=` и `shortable`.
- Балл 0..100 — только tie-breaker; сортировка везде: группа вердикта (buy/short → trim → hold/wait) → R/R → балл.
- **Лестница выхода для открытой позиции:** стоп в безубыток после +1R → chandelier 2·ATR после +2R → 50 % на цели → сокращение перед отчётом при P/L < 1R; `stop0` (стоп входа) хранится отдельно от текущего стопа, R считается от `stop0`. Лимит открытого риска книги 6 % капитала блокирует «Исполнить» → «В план».
- Бэктест плана в прототипе (22 бумаги, 2 года, вход по ретро-сигналам пересечения SMA50/отскока от S60, выход по стопу/цели по High–Low или через 15 баров): 115 сделок, 40 % прибыльных, средний −0.05R, PF 0.91 — **правила входа для маркеров требуют калибровки**; в приложении маркеры должны использовать те же условия, что и вердикт (откат к поддержке в тренде / отбой от сопротивления), а не пересечения SMA.

## 5. Модель сделки/позиции

- Позиция: расширение строки `r[]` полями через `d.xcols`/отдельный словарь `POS_META[tab][tk] = {side:'long'|'short', stop, target, riskKr, opened, planId}` (не ломает существующие индексы `r[6]` qty, `r[7]` price, `r[9]` avg). - Журнал `PF_TRADES`: без изменений формата; для шорта первая запись `act:'sell'` с флагом `short:true`, закрытие — `act:'buy'` с `short:true`. `pfTaxLots` обрабатывает пары как раньше (проверить тестом).
- Синк: новые ключи `posMeta` в `snapshotState` (app.js:17) + тест «snapshotState keys».
