# План: список покупок, тезис бумаги, «Что если?», рост бизнеса (референсы YU.invest)

Статус: **I1 и I2 сделаны (2026-09-10, итоги §8), дальше I3**; план — ред. 2, вопросы §6 решены — поправлен после ревью (§9) и дополнен скриншотами нового дизайна (§3). Implementation — отдельными сессиями I1–I3 (§7), каждая читает этот файл как источник правды.

Референсы:
- **YU.invest · Shopping list** — «7 акций на наступне падіння»: левая колонка-список 01/07 … + «Фінал», сетка карточек `сейчас → куплю` с «потрібна корекція ≈ −12 %», диапазоны цены покупки (`$100–110`, `≈ −22…−29 %`), тег категории (CORE / SOFTWARE / GROWTH / AI INFRA / HEALTH / VENTURE).
- **YU.invest · страница бумаги** (META, AMZN) — «Ключова теза» (заголовок + 1–2 предложения), «Моя зона покупки» (цена + пояснение «ціль для активнішої докупки» / «поблизу bear-case рівня»), «Рівень ризику» (5 делений + слово «Помірний»), три плитки `Reference price (дата) · Weighted fair value · Upside до fair value`, две плитки «Що саме купую» и «Головний ризик».
- **Сервис-аналитика** (MRVL, MELI) — «Доходи (Історія та Прогнози)»: столбцы факт / прогноз (пунктир), линия роста г/г на правой оси, «Історичні CAGR · Прогнозовані CAGR»; строка метрик «Капіталізація · Дивіденди 12м · Цільова ціна · P/E · Forward P/E · P/S · P/FCF»; блоки «Доходи / EPS: CAGR 5р · Прогноз 5р»; «Що якщо?» (портфель, Сума/Частка, быстрые суммы); «Оцінка аналітиків» (радар) и «Цільова ціна» (веер 1 год: мин/средн/макс); «P/E ratio» против пиров и против своей медианы.

Не входит: режим записи видео YU.invest (REVEALED / Reset / «Space reveal» / «4/4 відкрито») — это презентационная механика, не торговая. Слайды Games Global (сертификация игр) к этому плану не относятся.

Цель: добавить эти функции в существующий Trade Desk (`desk.js`/`desk.css`, флаг `dash_desk`) без замены `signals.js`, `chart.js`, `POS_META`, `PLAN_RULES`, `PF_TRADES` и синка. Решения пользователя из `plans/redesign-trading.md` §10 (R/R ≥ 2.0, риск 1 %, лимит книги 6 %, ручной флаг шорта и т. д.) не пересматриваются.

## 0. Принципы интерфейса

### 0.1 Минимальный полезный слой
Первый уровень каждого экрана — только: ситуация · рекомендуемое действие · ключевая цена · уровень риска · одна главная причина · одно основное следующее действие. Длинные объяснения, перечни индикаторов и несколько равнозначных главных кнопок на первом уровне запрещены.

### 0.2 «Как рассчитано»
У каждого вычисляемого результата — закрытый по умолчанию `<details>` «Как рассчитано» / «Подробности»: формула человеческим языком; исходные значения с единицами; курс валюты и время; комиссия и её состав; источник цены/таргета/финансов и время обновления; вход, стоп, цель, ATR, R/R, риск; значения до и после округления; применённые fallback-правила; время расчёта и `SIG.VER`; предупреждение об отсутствующих/устаревших данных. Не дамп объекта и не внутренние имена переменных.

### 0.3 Два уровня
Простой режим по умолчанию. Открытые «Подробности» можно запомнить на устройстве (localStorage, не синк); для нового пользователя всё свёрнуто.

### 0.4 Честные числа (новое после ревью)
Любое число или шкала на первом уровне обязано быть рассчитано и объяснимо в «Как рассчитано». Декоративные индикаторы (шкала риска «на глаз», счётчик позиций, подписанный как «риск») запрещены. Если данных нет — «—» и причина, а не подстановка.

### 0.5 Критическое не прячется
Блокировка исполнения, недостаток кэша, устаревшая цена, превышение лимита риска, «шорт не подтверждён», отчёт ≤ 3 дн видны всегда, даже при свёрнутых подробностях.

## 2. Модель данных

### 2.1 Список покупок `DESK_WATCH` (новый ключ снапшота `deskWatch`)

```js
DESK_WATCH = {
  v: 1,
  lists: [{ id: 'main', name: 'Список покупок', order: 0 }],   // одна по умолчанию; несколько — позже, без миграции формата
  items: [{
    id, key /* sym|ccy */, sym, tk, ccy, name, list: 'main',
    status: 'watch' | 'final',
    order,                                  // ручной порядок 01…NN
    tag,                                    // категория: CORE / GROWTH / … (свободный текст ≤ 16 симв.)
    buyLo, buyHi,                           // зона покупки (buyHi = buyLo, если одна цена); валюта бумаги
    buySrc: 'manual' | 'signal',            // signal = предложено SIG (лимит/уровень), manual = своя
    buyNote,                                // «ціль для активнішої докупки»
    thesis: { title, text },                // «Ключова теза»
    whatBuy, mainRisk,                      // «Що саме купую» / «Головний ризик» (заголовок ≤ 60 + пояснение ≤ 160)
    fv: { bear, base, bull, wBear: 25, wBase: 50, wBull: 25 },   // сценарии справедливой стоимости (необязательно)
    riskOvr,                                // ручной уровень риска 1–5 (null — авто, решение §6#1)
    refPx, refAt,                           // «Reference price» и дата фиксации (ставится при добавлении/по кнопке)
    planId,                                 // связанное правило PLAN_RULES (уведомление), если есть
    createdAt, updatedAt
  }]
}
```

Правила:
- `deskWatchNorm` — нормализация, дедуп по `key`, числа > 0 или null, строки обрезаются, неизвестные поля отбрасываются, `order` перенумеровывается.
- Синк по правилу CLAUDE.md «Новый ключ снапшота»: ветка в `snapshotState`, ветка в `applyRemoteState` **с защитой от старого клиента** (ключа нет ⇔ снапшот записал клиент до I1 → локальный список не затирается и пушится обратно, как `posMeta` в S3), ключ в `SNAP_KEYS` тестов (round-trip упадёт, если забыть). Бэкап в `dash_bak_*` — как `posMeta`.
- Связь с `PLAN_RULES`: кнопка «Уведомить» создаёт/обновляет правило входа (`level` = `buyHi` для лонга — сработает при касании верха зоны; `note` = тезис) и пишет `planId`; удаление идеи **не** удаляет правило (спрашивает). Сущности разные: идея — «хочу купить и почему», правило — «сообщи, когда цена там».
- Удаление идеи не трогает строку в исходной вкладке.

### 2.2 Справедливая стоимость и апсайд (чистые функции)

`deskFairValue(item, tgFull)` → `{ value, src: 'scenarios'|'analysts'|null, parts: [...], upsidePct }`:
- есть хотя бы `base` в `item.fv` → взвешенное среднее заданных сценариев (веса нормируются на сумму заданных), `src='scenarios'`;
- иначе есть `TG_FULL[tk]` с `low/consensus/high` → те же веса 25/50/25 по аналитикам, `src='analysts'`, подпись «по аналитикам»;
- иначе `null` («—, нет сценариев и таргетов»).
Апсайд — от текущей цены (не от `refPx`); `refPx` показывается отдельно как «цена на дату тезиса».

### 2.3 Уровень риска 1–5 (чистая функция, вместо декоративной шкалы)

`deskRiskLevel(snap, extra)` → `{ level, word, parts }`. Авто-значение (решение §6#1; проверить распределение на вселенной в I1, пороги — в одном объекте `DESK_RISK_CFG`, не в `SIG.CFG`, т. к. это не правило входа):
- база — дневной ATR %: ≤ 1.5 → 1 · ≤ 2.5 → 2 · ≤ 3.5 → 3 · ≤ 5 → 4 · > 5 → 5;
- +1 за каждый из: `wide`, `earnings`, `knife`, `stale-target`, бета > 1.5 (если есть в фундаментале); максимум 5;
- слова: 1 «Низкий» · 2 «Умеренный» · 3 «Средний» · 4 «Высокий» · 5 «Очень высокий».
В «Как рассчитано» — ATR %, какие надбавки сработали и почему. Распределение уровней по вселенной напечатать в итогах I1; если > 60 % бумаг получают один уровень — пороги поправить по решению пользователя.

### 2.4 «Что если?» — настройки и расчёт

Настройки: `DESK.whatIf = { mode: 'amount'|'weight', amountSEK: 5000, weightPct: 2, port }`. **`deskNorm` сейчас отбрасывает всё, кроме `riskPct/riskCapPct/shortOk`** — расширить его (clamp: сумма 100…10 000 000, доля 0.1…50) и тест `deskNorm` + round-trip ключа `desk`.

Чистая функция (результат не хранится):
```js
deskWhatIf({ tab, sec, side, plan, mode, amountSEK, weightPct, price, now })
// → { qty, notional, notionalSEK, feeNative, feeSEK, cashBefore, cashAfter,
//     weightBefore, weightAfter, sectorBefore, sectorAfter, ccyBefore, ccyAfter,
//     tradeRiskSEK, bookRiskBefore, bookRiskAfter, capSEK,
//     warnings: [{code, text, blocking}], status: 'ok'|'attention'|'blocked' }
```
- только существующие функции: комиссия `tradeFeeNative`, курс `FX`/`pf3Cv`/`pf3BaseFx`, капитал `pfEquitySEK`, риск `bookRiskState`/`deskCapCheck`, позиция `pfApplyTradeSide`; формулы не дублировать;
- количество — целые акции (дробных в приложении нет; если появятся — флаг портфеля, не угадывать);
- шорт: кэш меняется только на комиссию (как `deskExecApply`), вес считается по модулю, риск — до стопа сверху;
- предупреждения: `cap` (лимит книги, blocking), `cash` (кэш < 0 после сделки, blocking для лонга), `weight` (доля > 10 %), `sector` (> 35 %), `ccy` (> 60 % одной валюты кроме SEK), `nostop` (у плана нет стопа), `stale` (цена не live > 30 мин). Пороги концентрации — решение §6#3.
- Симуляция ничего не пишет в `DATA/POS_META/PLAN_RULES/PF_TRADES`/кэш — тест сравнивает `JSON.stringify` состояния до и после.

## 3. UI

### 3.1 «Идеи» = список покупок + вселенная

Над «Идеями» переключатель: `Все идеи` (текущая вселенная и фильтры) · `Список покупок` (status=watch) · `Финал` (status=final).

`Список покупок` (дизайн YU.invest):
- заголовок: `N акций на следующее падение` (редактируемое имя списка), подзаголовок «текущая цена → моя зона покупки», счётчик «Компаний N»;
- слева (≥ 1200 px) — нумерованный список `01/07 TK name` с точкой статуса (● зелёная — цена в зоне или ≤ 3 % до неё, ● серая — дальше) и пункт «Финал»; на меньших экранах — горизонтальные чипы;
- сетка до 4 колонок (≤ 900 px — 2, ≤ 560 px — 1); карточка: `TK · имя · тег`; `СЕЙЧАС $611 → КУПЛЮ $540` (или диапазон `$100–110`); `нужна коррекция ≈ −12 %` (диапазон `≈ −22…−29 %`); цвет полосы слева — вердикт v2; внизу мелко — вердикт v2 и R/R, если сигнал посчитан;
- действия карточки: клик → страница бумаги; `···` → «В финал / Вернуть», «Уведомить», «Изменить зону», «Вверх/вниз», «Удалить»; перетаскивание — только на десктопе с мышью, клавиатурный порядок — кнопками;
- «Добавить в список» — кнопка на карточке «Все идеи», в инспекторе и на «Акции»; зона по умолчанию = `buySrc:'signal'`: лимит-цена плана v2 (лонг) или ближайшая структурная поддержка; сразу доступна правка.

### 3.2 «Акция» — тезис сверху, торговый план ниже

Порядок блоков (заменяет D0-версию «Ключевой идеи»):
1. Шапка: тикер, имя, «профиль» (тег идеи или тип бумаги), цена, 1д, live/не live.
2. Строка из двух карточек: **«Ключевой тезис»** (из идеи; нет — авто из `why` с пометкой «авто по сигналу» и кнопкой «Написать свой») и **«Моя зона покупки»** (цена/диапазон, пояснение, **уровень риска 1–5 со словом** из `deskRiskLevel`). Бумага не в списке → вместо зоны — «Что делать» (вердикт v2 + вход плана) и кнопка «В список покупок».
3. Три плитки: **«Цена на дату тезиса»** (`refPx · refAt`; нет — текущая) · **«Справедливая стоимость»** (`deskFairValue`, подпись источника) · **«Апсайд до справедливой»**.
4. Две плитки: **«Что покупаю»** · **«Главный риск»** (из идеи; нет — скрыты, а не пустые).
5. Торговый план v2 (как в S6) и «Что если?» (§3.3), затем график цены, затем «Рост бизнеса» и «Аналитики» (§3.4–3.5), затем прочее свёрнуто.
Все поля идеи редактируются на месте (кнопка «Изменить» → форма; сохранение — `scheduleSave`).

### 3.3 «Что если?»

Компактный блок: портфель · `Сумма / Доля` · значение · быстрые суммы 5k/10k/25k/50k kr. Итог одной строкой: `N акций · новая доля X % · риск Y kr · статус`. После ввода — карточка «Сейчас / После покупки» (кэш, доля бумаги, сектор, валюта, открытый риск книги). Предупреждения — рядом с результатом, blocking — всегда видны. Кнопки: «В план» и (при праве `action.edit_trades`) «Исполнить…» → существующее окно исполнения с подставленным количеством. Ввод — дебаунс 250 мс, пересчёт на месте (как `deskExecRisk`), без перерисовки поля.

### 3.4 «Рост бизнеса» (история и прогноз)

Свёрнутый `<details>`; первое раскрытие — ленивый запрос одной бумаги.
- Столбцы по годам: факт — сплошные, прогноз — полупрозрачные с пунктирной рамкой; линия роста г/г на правой оси (как в референсе); переключатель `Выручка / EPS / FCF` (FCF — только факт).
- Подзаголовок: `Исторический CAGR X % · Прогнозный CAGR Y %` — прогнозный только при ≥ 2 точках прогноза, иначе «прогноз: N лет» или «прогноз недоступен».
- **Рисуется inline-SVG** (Chart.js в проекте нет — есть только lightweight-charts, который для категорийных столбцов не подходит; новая CDN-зависимость не нужна). Токены `desk.css`, тултип по наведению/фокусу: значение, валюта, «факт/прогноз», источник.
- Состояния: загрузка · нет данных · частичные (например, нет прогноза) · устарели (> 7 дн) · ошибка провайдера.
- «Данные и методика» (свёрнуто): таблица по годам, формула CAGR (`(последний/первый)^(1/лет) − 1`), источник и дата, какие годы исключены.

### 3.5 «Аналитики и оценка» (данные уже есть, воркер не нужен)

- **Строка метрик**: Капитализация · Цель аналитиков (+ %) · P/E · Forward P/E · P/S · (P/FCF — если появится FCF в §2.5). Источник — `VAL[tk]`, `TG_FULL[tk]`, `?targets` (cap). Цвет — только относительно медианы бумаги/сектора, иначе нейтральный.
- **Распределение рекомендаций** — горизонтальная полоса Strong Buy / Buy / Hold / Sell / Strong Sell из `TG_FULL[tk].ratings` (радар из референса не делаем — полосу читать проще).
- **Цель на 12 мес** — веер: последний год цены + три пунктирные линии к `low / consensus / high` через год. Рисуется в `chart.js` отдельной функцией-моделью (тест) на lightweight-charts (линии по времени — его формат).
- **P/E**: против пиров (бумаги того же сектора из вселенной с `VAL.pe`, 5–8 штук, полоса-шкала как в референсе) и против своей медианы 3/5 лет (`VAL.hist.pe3/pe5`) — числом и отклонением в %, без графика истории (ряда нет).

## 5. Критерии приёмки

1. Симуляция не меняет портфель до явного подтверждения (тест).
2. Все денежные результаты учитывают валюту и комиссию; формулы — только существующие функции приложения.
3. Лимит открытого риска блокирует исполнение так же, как в S6.
4. Шорт в «Что если?» зеркален и не считается покупкой.
5. Список покупок синхронизируется, переживает запись старым клиентом и не конфликтует с `PLAN_RULES`.
6. Факт и прогноз визуально и текстом различимы; прогнозы не выдумываются.
7. Открытие Trade Desk не запускает финансовые запросы — только раскрытие «Роста бизнеса» у открытой бумаги.
8. На 390 px нет горизонтальной прокрутки.
9. Все тесты зелёные, новые группы: deskWatch, deskFairValue, deskRiskLevel, deskWhatIf, financials (worker).
10. Первый уровень — только нужное для решения; «Как рассчитано» закрыто по умолчанию, но есть у каждого важного числа.
11. На первом уровне нет декоративных чисел и шкал (§0.4).
12. Критические предупреждения видны всегда (§0.5).
