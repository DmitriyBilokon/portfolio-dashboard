Источник правды для S7b-2…S7b-5 — этот файл; общие правила и критерии — [redesign-integration.md](redesign-integration.md) §7.5/§7.7/§9 и [stock-selection-ux.md](stock-selection-ux.md) §9/§17.3.

## 1. Инструмент

`node plans/redesign-trading/s7b-graph.js <режим>` (нужен acorn: любой `node_modules` с ним, `npm i -g acorn` или `ACORN=/путь`; на этой машине берётся из `~/.npm/_npx`). Граф на 2026-09-11: **1170 узлов** (top-level объявления и инструкции 11 клиентских файлов в порядке `index.html`), **4537 рёбер в коде + 155 из строк** (inline `onclick="…"`). Рёбра учитывают локальные области (параметры, `var/let/const`, `catch`, `for`); динамических обращений `window[…]`/`eval` в клиентском коде нет — граф статически полон.

| Режим | Что даёт |
|---|---|
| `who <имя…>` | кто ссылается и на что ссылается имя, какие DOM-id читает/создаёт |
| `reach [cut.json]` | что станет недостижимым в модели `s7b-cut.json` (🧪 — есть в тестах, [метки] — какой вход классики держит узел) |
| `why <имя…>` | кратчайший путь от корня (top-level инструкция или `keep`) — кто держит узел живым |
| `writes [cut.json]` | кто пишет глобальные хранилища; с моделью — хранилища, потерявшие писателей (данные перестанут обновляться) |
| `free` | свободные имена (не объявлены, не встроены браузера) в коде и inline-обработчиках — **после каждого удаления должно быть пусто**; сейчас пусто |
| `ids [id…]` / `css [--file=…]` / `json` | DOM-id: кто создаёт/читает; классы CSS и файлы, где они упомянуты (скан по словам — шумный, для S7b-4) |

`plans/redesign-trading/s7b-cut.json` — **модель конечного состояния**: `keep` — функции классики, которые desk зовёт после переноса (S7b-2); `rewire` — смешанные функции после правки (`renderAll`/`renderPF3` → только `deskRender`, `init` без навигации, `index.html` только оверлеи); `dropEdges` — ссылки, которые уходят при правке живых функций (адаптеры SIG, очистка «Реком. скоринг»). `reach` по модели = список удаления S7b-3: **243 узла, ~210 КБ** (app.js 77/58.8 КБ, app-2 53/54.2, app-3 36/38.3, app-4 38/36.8, app-5 32/20.4, desk.js 6/1.7) + классическая разметка `index.html` + неиспользуемый CSS (S7b-4). Без переноса (просто отрезать оболочку) недостижимыми стали бы 430 узлов/380 КБ, включая K4, «Структуру», AI Proto, дивиденды — потерю функций модель и ловит.

## 2. Решения пользователя 2026-09-11 (открытые пункты S7b)

1. **Карточка акции** — переносятся все четыре предложенных блока: пре/пост-маркет и объём дня, правка позиции (кол-во/средняя без записи сделки), подробная оценка (EV/EBITDA, PEG, «ловушка стоимости», пиры, изменения таргетов за 30 дн), **сценарии bull/base/bear + implied move**. Отменяются: фильтры и таймлайн инсайдеров, «последний квартал» в «Здоровье бизнеса», пара таргетов «свежий против всего времени».
   ⇒ `scenarioShort/Mid/Tech/Projection`, `SCENARIO_CFG`, `scnFreshTarget`, `pf3OptEnsure`, `atrFromCloses`/`rsiFromCloses`/`weeklyFromCloses` **остаются** — только как блок «Сценарии» (отображение). Их прочие потребители уходят: вход в `pf3RecoHorizons` и алерты `scnAlertCheck`. Критерий «`grep scenarioShort` пуст» (integration §9, §7.7 п.6) заменяется на «`scenarioShort` — только в блоке «Сценарии» и его тестах».
2. **AI-прогноз** стоимости портфеля (админ, `?action=forecast`) — переносится в AI-раздел книги; детерминированный прогноз (`pf3ForecastHTML`, `pf3Fcast12`, `homeForecastPicks`) удаляется по исходному плану (redesign-trading §4). `pf3FcTable` остаётся (таблица AI-прогноза).
3. **«Реком. скоринг»** (колонка строк, которую писал `pf3WriteReco`; воркер берёт её вердиктом AI-портфеля, пустую добивает `aipVerdict`) — клиент **очищает колонку** одноразовой миграцией (`SCHEMA_V=3`) и больше не пишет. Поведение AI-портфеля не меняется (воркер считает `aipVerdict` той же логикой), деплой не нужен. Колонку из `headers` не убирать — схема строк индексная. Перевод воркера на SIG — отдельная задача (§7.7 п.5).
4. **Сектора** — в «Идеях» добавляется фильтр по сектору; Live Sector Tracker (вкладка «🔄 Сектора», `sect*`) удаляется.

`--v3-acc`/`--v3-acc2` (фиолетово-бирюзовый акцент `pf3-btn`/`pf3-logo`/`pf3-row-logo`/`pf3-bar-fill`/`airk-hz-it.sel` и т.п.) раньше жили только в `body.v3{}` — перенесены в `html.desk{}` (те же значения, обе темы). Также в `html.desk` добавлены алиасы `--green-bg/-t`, `--red-bg/-t`, `--yellow-bg/-t` → `--dk-*-soft`/`--dk-*` (раньше — только `--green/--red/--yellow`, без `-bg`/`-t` вариантов) и литералы `--gold`/`--blue-bg`/`--blue-t`/`--purple-bg` (с явными светлым/тёмным значениями) — без них строки, где эти переменные раньше брались из удалённого `:root`, стали бы прозрачными.
