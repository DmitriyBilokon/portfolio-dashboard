## 1. Цель и связь с удалением классики

Пользовательский путь: найти 5–10 кандидатов → сравнить → оставить 1–3 → проверить цену и риск для выбранного портфеля → добавить в список или план.

**Конечный продукт — Trade Desk как единственный интерфейс. Классика удаляется в S7b.** Это решение уже зафиксировано в [плане слияния](redesign-integration.md), §5–7, и [плане редизайна](redesign-trading.md), §4/8. Настоящий план уточняет UX отбора компаний и подготовку к S7b; он не отменяет удаление классики.

До S7b классика временно обеспечивает доступ к неперенесённым функциям. После S7b удаляются старые экраны, переключатель оболочки и переходы через deskClassic. Старый URL ?desk=0 открывает Trade Desk, а не удалённую оболочку. Общие расчёты, данные и серверные функции сохраняются, пока у них есть действующие потребители.

Условия входа S7b сохраняются: неделя использования desk и завершение теневого сравнения сигналов с разбором расхождений. На 2026-09-11 выполнение этих условий не подтверждено: S6/S7a датированы 2026-09-10. Истечение времени само по себе не является приёмкой. P1–P4 могут выполняться во время наблюдения; накопление новой статистики P5 не задерживает S7b.

Первый уровень интерфейса показывает вывод и следующий шаг. Методика и подробные таблицы раскрываются по запросу; критические предупреждения остаются видимыми.

## 3. Модель решения

### 3.1 Граница данных и вычислений

Будущий адаптер deskSelectionInput собирает вход из существующих источников: secFromRow/deskUniverse, снимок SIG, PF_FUND, VAL, TG_FULL, список покупок, позиция выбранного портфеля, права и время данных.

Чистая модель получает аргументами:

    identity: key, sym, ccy, sector
    price: value, observedAt, freshness
    business: pillars, mode, asOf, missing, notApplicable
    valuation: value, source, currency, asOf, warnings, peContext
    signal: verdict, side, plan, phase, flags, why, version
    risk: auto, override, level, reasons
    position: tab, side, action (результат deskPosAct или null)
    context: selectedPortfolio, permissions, now, config

Результат:

    quality: value, labelKey, mode, coverage, missing, notApplicable
    valuation: value, source, status, reasonCodes
    timing: verdict, side, plan, reasonCodes
    risk: auto, override, level, reasonCodes
    action: key, source, reasonCodes, warnings, nextStep
    selection: eligible, buckets, reasonCodes

Идентичность бумаги — существующий биржевой ключ, а не один тикер. ASML USD и ASML EUR не склеиваются; одна бумага из нескольких вкладок дедуплицируется с сохранением принадлежности. При нескольких позициях по одной бумаге действие относится к выбранному портфелю. Из режима «все портфели» для сделки сначала выбирается конкретный портфель.

Часть старых кэшей хранится по тикеру. Адаптер проверяет валюту/листинг перед использованием; если однозначное соответствие установить нельзя, поле помечается несопоставимым и не участвует в оценке. Новый биржевой ключ модели сам по себе не исправляет неоднозначность старого кэша.

Доступ фильтруется до расчёта и отображения, включая сравнение. Чистые функции не читают DATA/VAL/FX/DOM/Date.now, не вызывают fetch и не сохраняют состояние. Причины возвращаются кодами; перевод и форматирование выполняет UI. Отсутствующее число не превращается в ноль.

### 3.2 Четыре измерения

| Измерение | Источник | Смысл |
|---|---|---|
| Компания | Бизнес-столпы pf3Betyg | Прибыльность, рост, баланс, денежный поток |
| Цена | deskFairValue и существующие сравнения P/E | Цена относительно оценки с указанием источника |
| Момент | SIG.snapshot через адаптер | Технический сетап и условия входа |
| Риск | deskRiskLevel и контекст выбранного портфеля | Риск бумаги и ограничения конкретной сделки |

Измерения разделены по смыслу, но не объявляются статистически независимыми.

**Компания.** pf3BetygRow возвращает только сводный результат. Для качества адаптер получает pillars из pf3Betyg(F, tk, sector), исключает val и использует относительные веса profit/growth/balance/cash существующего Betyg: 0.25/0.20/0.20/0.20. Источник весов сделать общим с pf3Betyg, сохранив исходные результаты тестами; формулы столпов не копировать.

Coverage = сумма весов известных применимых бизнес-столпов / сумма весов всех применимых бизнес-столпов. Значение качества рассчитывается по известным столпам; при неполном покрытии оно предварительное и не участвует в подборке полного качества. Нет ни одного столпа — value=null.

Для банка balance/cash помечены notApplicable и не штрафуются как пропуски. Даже при coverage 100% выводится «оценка по 2 применимым столпам», а не «все показатели проверены». Для полного вывода нужны все применимые столпы и не менее двух известных. Буква качества использует существующую шкалу pf3Grade.

pf3RowBetyg также включает оценку и не подходит как готовое число качества. При наличии только строки показывать факты ROE/роста с меткой «предварительно», без полного рейтинга. ROE-lite финансовой компании сам по себе не даёт вывода «плохой бизнес». Полный пятистолповый Betyg остаётся в подробностях со своим названием и составом.

**Цена.** Оценка пользователя, консенсус аналитиков и исторический P/E подписываются отдельно. `TG_FULL` сейчас хранится без валюты (`app-3.js:293`: `{...t, at}`) — при загрузке таргетов сохранять `ccy`/`sym` листинга, по которому они запрошены (как `VAL`), иначе адаптер честно считает их несопоставимыми и «Дисконт к оценке» всегда пуст. Таргеты Yahoo приходят без `lastDate` — статус `undated`, в «Дисконт» не попадают, но в измерении «Цена» видны с пометкой. Ручная fair value не делает бумагу автоматически лидером общей подборки. Валюта/масштаб должны быть сопоставимы с ценой; неизвестная дата не называется свежей. Отсутствие оценки не означает «дорого». Отрицательный EPS исключает обычное сравнение P/E, но не бумагу.

**Момент.** Сохраняются SIG.verdict, направление, market/limit и причины. Цена ожидания берётся из существующего плана/зоны. Если уровня нет — «уровень не рассчитан». Ручная зона списка и текущий план SIG имеют отдельные подписи.

**Риск.** Ручной override виден рядом с автоматическим уровнем и не снимает системные блокеры. Кэш, размер и лимит книги проверяет существующий путь deskWhatIf/deskCapCheck/deskExecApply. Их формулы не переносятся в модель отбора.

Свежесть цены и факт последней загрузки — разные поля. Порог пригодности цены переиспользует существующий DESK_IDEA_CFG.whatIf.staleMin; неизвестное время не считается свежим. Для финансовых данных различать fetchedAt и дату отчётного периода: семь дней кэша не означают, что годовая отчётность обязана быть недельной давности. Известный stale-target сохраняется; неизвестная дата источника оценки даёт предупреждение.

### 3.3 Главное действие

Приоритет:

1. Для открытой позиции сохранить deskPosAct: exit/take/trim/earn/trail/be/nostop/watch/hold. Сработавший стоп не скрывается высоким качеством, отсутствием фундаментала или предложением нового входа. Свежесть цены проверяется перед исполнением.
2. Для новой позиции сохранить технический результат SIG. При отсутствии пригодной цены/сигнала следующий шаг — обновление. При неполном фундаментале — «Проверить компанию» с отдельной подписью «технический сетап: …».
3. SIG.buy означает «Кандидат на вход», а не разрешение сделки любого размера. Основная кнопка — «Проверить сделку» с существующими правами, предпросмотром и лимитами.
4. SIG.wait/hold без позиции — «Ждать уровня» или «Изучить» в зависимости от данных. SIG.short ведёт в технический сценарий и не означает «Продать» для владельца лонга.
5. Knife, близкий отчёт и прочие действующие блокеры ограничивают новый вход по правилам SIG; они не прячут выход по уже открытой позиции.

research — состояние процесса проверки данных, а не ещё один торговый вердикт avoid. Нельзя получить «Купить» только по качеству/дисконту вопреки SIG. Все критические предупреждения сохраняются, даже если их больше, чем предусмотрено компактной компоновкой.

AI показывается как отдельное мнение с датой и горизонтом. Расхождение с SIG раскрывается явно. UX-обёртка не переписывает ни AI, ни правила и не придумывает объяснение изменения мнения без данных.

### 3.4 Подборки вместо нового общего score

**Новый deskPickScore и веса 35/25/25/15 отложены.** Методика не проверена, факторы пересекаются с SIG.score и Betyg. В P1–P4 добавляются четыре измерения и явные правила отбора.

deskPickBuckets определяет принадлежность к подборкам. Для двух доступных снимков порядок внутри подборки — существующий SIG.cmp, переданный адаптером как аргумент compareSignals; при равенстве — стабильный биржевой ключ. Чистый модуль не читает глобальный SIG. Бумаги без снимка сортируются после бумаг со снимком, между собой — по ключу; в подборки первого выпуска они не попадают (вердикт неизвестен, поэтому и в «Нужно изучить» тоже нет — §15 #2). Подробная таблица сохраняет пользовательскую сортировку.

Конфигурация новых UI-правил — DESK_IDEA_CFG.selection: до 12 карточек, до 4 бумаг сравнения, пул новых загрузок 2. Близость — существующий nearZonePct, торговые пороги — SIG.CFG, качество — шкала pf3Grade. Отдельный DESK_PICK_CFG с дублирующими порогами не вводится.

Эксперимент общего ранга возможен после P5 отдельным планом и версией с сравнением против текущей базы. Ни четыре измерения, ни технический score не называются вероятностью прибыли.

## 4. Экран «Акция»: три режима

Общая шапка: компания, биржа/валюта, цена и свежесть, выбранный портфель. При открытой позиции её сторона и срочное действие видны во всех режимах.

### Решение — по умолчанию

Краткий вывод, четыре измерения, цена ожидания с источником, главный риск и одна primary-кнопка. Для позиции — стоп/цель и действие позиции. Компактный результат «Что если?» виден, подробная форма открывается явно.

Следующая кнопка определяется задачей и правами: «Обновить данные», «Проверить компанию», «Добавить в список», «Уведомить», «Проверить сделку» или действие позиции. Существующее уведомление не создаётся повторно. Просмотр карточки не записывает ничего в план/список/портфель.

### Компания

Тезис, бизнес-столпы, выручка/EPS/FCF, оценка, события, новости и инсайдеры. Ключевые графики и существенные факты видны; подробные таблицы/формулы — в details. Все блоки не нужно скрывать одновременно: пользователь должен видеть основания вывода. AI — вторичный блок с текущей проверкой прав.

Нужные части полной классической карточки переносятся сюда. Ссылка «Ещё → классика» временная и удаляется после проверки полноты переноса.

### Техника

Большой график, период/слои, план выбранной стороны, уровни, фаза и история сигналов. Long/Short здесь меняет только моделируемую сторону; он не меняет открытую позицию и не должен незаметно менять лонг-отбор в других режимах.

Линия «прибыль × P/E» остаётся слоем графика. Её данные используются в «Компании» через общий кэш, без второго загрузчика.

### Навигация и жизненный цикл

DESK_UI.stockView хранится в памяти. Первый прямой вход — «Решение»; Back восстанавливает режим, фильтры и прокрутку. В P2 расширить существующий маршрут/history-state без второго роутера.

deskChartsAttach проверяет наличие контейнера. При уходе из «Техники» график и наблюдатели освобождаются; переключения не дублируют канвасы. Поздний ответ сохраняется в кэш своей бумаги, но не переключает текущий экран и не перезаписывает ввод.

Новые рендереры получают контекст бумаги явно. Существующие AI-обработчики, зависящие от v3Key/pf3Sel, проверяются при переключении между бумагами во время запроса; результат привязан к исходной бумаге, а не текущему глобальному выбору.

## 5. Экран «Идеи»

Подборки находятся внутри «Все идеи». «Список покупок» и «Финал» сохраняют ручной порядок и смысл; алгоритм их не переставляет.

| Подборка | Условия первого выпуска |
|---|---|
| Кандидаты сейчас | SIG.buy, лонг, пригодная цена, полный применимый бизнес-срез, без блокеров нового входа. **Оценка не обязательна** (решение 2026-09-11, §15): показывается отдельным измерением с источником/датой/статусом |
| У зоны покупки | Лонг с действительным лимитным планом и расстоянием в существующем nearZonePct; сломанный сетап не считается хорошим входом |
| Качественный рост | Полный применимый бизнес-срез A/A+ и положительный фактический рост выручки; прогноз не заменяет факт |
| Дисконт к оценке | Сопоставимая внешняя оценка выше цены, известная дата, без knife/известного stale-target; источник подписан |
| Нужно изучить | **Почти кандидаты**: лонг SIG.buy или действительный лимит у зоны, которым до «Кандидатов»/«У зоны» не хватает только данных (бизнес-срез не полный, цена/сигнал не пригодны) — с причиной и кнопкой догрузки. Остальные бумаги с пропусками сюда не попадают (§15 #2) |
| Высокий риск | Автоматический риск 4–5 или критический флаг; ручное снижение риска не исключает бумагу |

«Кандидаты сейчас» не обещает лучшие инвестиции; подпись подборки берёт итог P0.5 (историческое преимущество входа SIG против ориентиров), а не общие слова. «Дисконт к оценке» не утверждает истинную недооценку. Short остаётся в существующих технических фильтрах; новый фильтр «PF > 1» не вводится — одиночный PF не доказывает надёжность.

Каждая подборка объясняет правило, показывает до 12 результатов и общее число подходящих. Категории могут пересекаться. Пустой список объясняет отсутствие сетапов/данных; его не заполняют менее проверенными бумагами ради количества.

Карточка: имя, четыре измерения, цена → уровень при наличии, причина и действие. R/R/SMA/ATR доступны в подробностях, кроме непосредственной причины блокировки. Перестановка списка при догрузке не уводит фокус и активную карточку из-под курсора: новый порядок применять после окончания ввода или явного обновления.

## 6. Сравнение 2–4 компаний

Выбор по биржевому ключу в DESK_UI.compare, до 4 бумаг; checkbox не добавляет бумагу в список. Route #desk/compare добавляется в whitelist, рендер, подписи и историю. Back возвращает исходную подборку/фильтры/прокрутку. Прямая ссылка без локального выбора предлагает выбрать бумаги.

Сравнивать действие, бизнес-столпы и coverage, рост/FCF, P/E-контекст, оценку, расстояние до входа, R/R, риск и отчёт. Первый вид — ключевые различия, остальные строки раскрываются.

Сопоставимость требует одинакового типа периода (FY/TTM/прогноз), валюты/масштаба и отраслевой применимости. Абсолютная выручка не означает качество; отрицательный EPS не даёт «самый дешёвый P/E». Рост через нулевую/отрицательную базу EPS не показывается обычным процентом. Грубого совпадения сектора недостаточно для признания компаний прямыми пирами.

Подсветка лучшего/худшего — только для сопоставимых значений. Вместо универсального «A лучше B» выводить «Чем отличаются условия»: конкретные факты по измерениям.

«Что если?» рассчитывается независимо для каждой бумаги при одинаковом выбранном портфеле/бюджете; варианты не считаются одновременно доступными покупками на один и тот же кэш. «В финал» использует существующие deskWatch-мутаторы и права. Смена аккаунта/доступа очищает недоступный выбор и результаты.

## 7. Журнал результатов выбора — P5

Первый журнал проверяет исходы **явно выбранных пользователем идей**. Это смещённая выборка, а не тест отбора всей вселенной. SIG.replay и реальные PF_TRADES остаются отдельными источниками.

Запись по явной кнопке «Отслеживать результат», а не при рендере. Дедуп по бумаге/версии/UTC-дате. Исходные поля неизменяемы; удаление из списка не удаляет наблюдение.

    id, recordedAt, key, sym, ccy, source=manual-selection
    selectionVersion, signalVersion, bucket, dimensions
    observedPrice, observationAsOf
    benchmark: symbol, currency, basis
    entry: null до появления условного входа
    horizons: 20/60/120 торговых дней, каждый pending/missing/complete
    costAssumptions, status

Условный вход — закрытие первого полного дневного бара после записи, с учётом локальной даты сессии биржи; не сегодняшний незакрытый бар. Это расчётная точка, не исполненная сделка. Далее отсчитываются 20/60/120 торговых баров бумаги. Если время сессии неизвестно, вход pending. Пропуски данных не дают нулевой доходности.

Бенчмарк фиксируется при записи: USD — S&P 500 (^GSPC), SEK — OMXS30 (^OMX). Для других валют сначала абсолютный результат без альфы с явной пометкой. Индекс и бумага сравниваются на одинаковых датах; при отсутствии одной даты альфа не рассчитывается.

Результат — ценовая доходность в валюте бумаги без дивидендов; альфа = результат бумаги минус индекс за те же даты и в той же валюте. SEK-результат иностранной бумаги требует исторического FX и не имитируется сегодняшним курсом. При неподтверждённой сопоставимости цен после split результат помечается как несопоставимый.

Условный net после комиссии — отдельный показатель, использующий существующую модель с зафиксированной суммой/количеством/FX и версией допущений. Если этих полей нет, net не рассчитывается. Сценарий не называется фактической доходностью портфеля.

Хранение — отдельный localStorage-ключ с пространством аккаунта; без расширения ledger/shared_analysis/worker. Анонимные наблюдения не пишутся. Ошибки/квота хранилища видны, а не проглатываются. Завершённые записи хранятся 365 календарных дней после завершения последнего горизонта; pending не удаляются по возрасту. Перед кодом P5a зафиксировать лимит размера и формат экспорта; при достижении лимита предлагать экспорт/очистку завершённых, не удалять pending молча.

Обновление — при открытии журнала через существующую историю, пул 2. При закрытом сайте наблюдение не ведётся; при следующем открытии возможен догоняющий расчёт. Разделять версии/горизонты/long-short; исходные признаки не пересчитывать сегодняшним фундаменталом.

До 30 завершённых наблюдений в группе — «мало данных». При большем количестве показывать N, период и распределение, не заявлять доказанную точность. Перекрывающиеся периоды одной бумаги не являются независимыми испытаниями. Реальные 120 торговых дней нельзя проверить в одной сессии: используются датированные фикстуры, а живой результат остаётся будущей проверкой.

## 8. Архитектура, загрузка и состояние

С P1 чистая модель помещается в **desk-selection.js**. Он подключается перед desk.js; порядок: app-5.js → desk-selection.js → desk.js → desk-gloss.js. При загрузке модуля нет обращений к DOM/глобальному состоянию; всё передаётся функциям аргументами.

Тестовый раннер tests/run-app.js, index.html и фильтр .githooks/pre-commit должны включать новый модуль. Версии ?v= по-прежнему выставляет хук.

Начальные «Решение»/«Идеи» читают имеющиеся строки и кэши. Новая полная загрузка — при открытии «Компании», сравнения и явной кнопке «Обновить данные кандидатов» (до 12). Не вызывать pf3LoadAllFundamentals для всей вселенной. Существующая фоновая загрузка котировок/сигналов сохраняется.

Пул новых запросов — 2, дедуп по биржевому символу и типу запроса, действующие TTL и негативный кэш. График/линия прибыли используют общий кэш по [earnings-line.md](earnings-line.md). Переход на вкладку сам по себе не должен повторять свежий запрос.

Ключ вычисленной модели учитывает обновления цены/времени, версии сигнала, фундаментала/оценки, ручных полей, портфеля и прав. Поздний ответ старого аккаунта не попадает в новый UI. Отказ одного источника сохраняет остальные измерения.

## 11. Критерии приёмки

1. За 5 секунд ручного UX-сценария пользователь находит состояние компании, оценку цены, следующий шаг и главный риск.
2. Первый экран ориентируется на 7 смысловых элементов и одну primary-кнопку. Срочный выход и критические предупреждения не скрываются ради этого ограничения.
3. Источники, даты, пропуски, предварительные и неприменимые данные различаются. Изменение val не меняет качество бизнеса.
4. Высокое качество не отменяет SIG.wait; мало данных не даёт метку полной проверки.
5. Доступная аналитика читается без торговых прав, запись требует действующих прав/проверок.
6. До 12 кандидатов без обязательной настройки сложных фильтров; пустая выборка объяснена. Сравнение не подсвечивает победителя по несопоставимым данным.
7. Просмотр/сравнение не меняют портфель, список и план; журнал записывается явно.
8. Открытие desk не добавляет массовый fetch фундаментала. Переключения не дублируют канвасы/загрузки и не теряют ввод.
9. Проверены 1440/1024/390 px, RU/EN, dark/light, клавиатура, aria-selected/expanded, видимый фокус и reduced-motion. На 390 px нет горизонтальной прокрутки страницы.
10. До S7b проверяется временный возврат в классику. После S7b старый UI/переключатель отсутствуют, нужные функции доступны в desk, включая auth/настройки/K4/семейные портфели.
11. Проверены новый пользователь, роль без сделок, смена аккаунта, медленная сеть, отказ источника и неизвестная дата.
12. Тесты зелёные; ручная приёмка перечисляет выполненные сценарии и те, которые требуют пользователя/живых данных.

## 12. Проверки

После кода: bash tests/run.sh, git diff --check, per-file JSC new Function для изменённых JS. Если доступен навык check-syntax — использовать его; иначе эквивалент по CLAUDE.md. Новый модуль загружается тестами в порядке index.html, без boot/deskBoot.

P1: null/ноль/NaN/отрицательный EPS; полный/частичный/пустой бизнес-срез; банк с неприменимыми полями; val не влияет на качество; прежний Betyg не меняется; валюта/дата оценки; quality high при SIG.wait; exit при отсутствии фундаментала; short/long; override не снимает блокер; тикер на двух биржах; SIG.cmp и стабильный tie-breaker; входные объекты не мутируют.

P2–P4: поведенческие DOM/навигационные проверки, не копия полной HTML-строки; переключение во время загрузки, уничтожение графика, Back/Forward, выбор 0/1/2/4/5 бумаг, снятие доступа, клавиатура, независимость сравниваемых сценариев, сохранение ручного порядка. Сетевые счётчики подтверждают пул/дедуп и отсутствие новых массовых загрузок.

P5: запись не меняется будущими данными; условный вход строго после записи; незакрытый бар/таймзона, торговые дни и пропуски; pending отличается от нулевого результата; split/FX/комиссии; разделение версий/аккаунтов; ошибка localStorage; pending старше 180 дней сохраняется. На исторических фикстурах проверяется причинность, а не создаётся видимость уже накопленной живой статистики.

S7b: поиск действующих ссылок на удалённые функции, независимый boot, старые URL/localStorage/SW, общие стили auth/AI/модалок, RBAC, книга/налоги и сохранение на тестовой копии данных. Архивная документация не считается действующим потребителем функции. Живой AI запускает пользователь; просмотр уже сохранённого результата проверяется отдельно.

1. **Второй канвас после возврата в «Технику»** (было и до P2 при уходе со страницы во время загрузки): состояние графика отбрасывалось без смены токена, поздний ответ рисовал график в новый контейнер поверх нового и оставлял неосвобождённый ResizeObserver.
2. **AI-снапшот чужой бумаги** (`stockAiSnapshot`, app.js): собирался после `await` и брал фундаментал через `pf3FundData()` — по текущему выбору `v3Key/pf3Sel`; переход к другой бумаге во время AI-запроса подставлял её отчётность. Теперь — кэш карточки только при совпадении символа, иначе `PF_FUND` своей бумаги (тест).
3. **`pf3RefreshCardPrice`** (app-5.js) пересчитывал строку `recalcPF(i, v3Key)` по вкладке, выбранной к моменту ответа; теперь вкладка фиксируется до `await` (параметр `tab`, классика без изменений поведения).

`pf3NewsEnsure` (app-3.js) теперь возвращает промис загрузки — для пула; классика результат не использует.

### 17.4 Проверки и ограничения

- **Headless-смоук** (Chrome по CDP, сид `data.js`, Supabase заблокирован → локальный режим, воркер цен — настоящий, только чтение; бумага MU): «Решение» → «Компания» (догрузились отчётность, `?earnings=`, 10 новостей; вывод сменился с «Проверить компанию» на «Ждать уровня», качество A 8,2/10) → «Техника» (1 экземпляр графика) → обратно и быстрые переключения (по-прежнему 1) → «Идеи» → Back (бумага вернулась в «Технику»). 1440 и 390 px без горизонтальной прокрутки, RU/EN, тёмная/светлая, одна primary-кнопка в «Решении», ошибок JS нет. 1024 px, клавиатура и reduced-motion в живом браузере не прогонялись.
- **Требует пользователя / живых данных:** роль без сделок и смена аккаунта (RBAC Supabase), AI-запуск из «Компании» и переход к другой бумаге во время ответа, реальная позиция с пробитым стопом (кнопка «Продать…»), Back/Forward и прокрутка в обычном браузере и на iPhone.
- Back ставит прокрутку после первой перерисовки: если экран ещё без догруженных данных, браузер ограничит её высотой страницы.
- «Решение» для бумаг вне моих портфелей почти всегда начинается с «Обновить данные» — у них нет live-котировки (модель P1 требует свежую цену). Одна кнопка — один запрос `?symbols=` и свечи; массовой загрузки нет.
- Старые `TG_FULL` без `ccy` в «Решении» дают «оценка несопоставима … нужен перезапуск «📐 Оценка»» (кнопка пока только в классике — §15.1).
