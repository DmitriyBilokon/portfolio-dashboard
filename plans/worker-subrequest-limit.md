# План: фикс «Too many subrequests» в воркере (Cloudflare free = 50/вызов)

Статус: **Implementation ВЫПОЛНЕН** (30.06.2026). Осталось: ручной деплой воркера + `verify-worker` + ручная проверка крона.

Сделано:
- `yahooLite()` (chart-only, 1 подзапрос) → применён в `liveMarkets`, `buildPortfolioSnapshot`, `aiPortfolioRun` (котировки/исполнение). Карточные эндпоинты — на полном `yahoo()`.
- `runPortfolioAnalyses` → заменён на `analyzeOnePortfolio(env, key, force)` с per-portfolio гейтом `data[key].pfAnalysisAt`.
- `pickCronTask(minute)` (чистая, тест в cases-worker.js): 0–19 цикл · 20–39 PF3 · 40–59 Anna. `scheduled` запускает ОДНУ задачу за тик.
- `?action=aiport` → только цикл; добавлен `?action=pfanalyze&key=` (ручной анализ одного портфеля).
- `WORKER_BUILD` = `2026-06-30subreq-split`. `check-syntax` ✅, `tests/run.sh` ✅ (вкл. pickCronTask).
- Оценка/вызов: цикл ≈26, анализ ≈33 подзапроса (< 50).
Тип: bugfix воркера `telegram-notify.js`. Тариф — **Free (лимит 50 подзапросов на ОДИН вызов воркера)**. Деплой воркера — вручную пользователем.

## Корневая причина
Один вызов воркера (`scheduled` cron и кнопка `?action=aiport`) делает >150 fetch-подзапросов:
- `aiPortfolioRun` — котировки позиций + бенчмарки (~25–35).
- `runPortfolioAnalyses` — для ДВУХ портфелей, каждый: `buildPortfolioSnapshot` (по `yahoo()` на позицию) + `liveMarkets()`.
- **`yahoo(sym)` = 2 подзапроса** (yChart + yQuoteSummary) на каждую позицию (~15×2=30 на портфель).
- **`liveMarkets()` ≈ 28** (14 символов × 2), вызывается отдельно в каждом анализе (×2 = 56).

На free (50) бюджет исчерпывается ещё до конца → падает на анализе Dima (он идёт после цикла + первого анализа).

## Цель
Каждый вызов воркера должен укладываться в **≤ ~40 подзапросов**. Достигается двумя независимыми мерами: (A) снизить подзапросы, (B) разнести задачи по разным вызовам.

## A. Снизить подзапросы
1. **`yahooLite(sym)`** — облегчённая котировка: ТОЛЬКО `yChart('1d','1y')` (1 подзапрос), без `yQuoteSummary`. Возвращает `{price, pct, sma50/100/200, support, resistance}` (день% — из chart-фолбэка, который уже есть в `yahoo()`). Вынести общий парсинг chart→levels, чтобы не дублировать.
2. Использовать `yahooLite` вместо `yahoo` в массовых путях:
   - `buildPortfolioSnapshot` (котировки позиций) → ~15 вместо ~30 на портфель.
   - `liveMarkets` → ~14 вместо ~28.
   - `aiPortfolioRun` котировки позиций и re-quote на исполнении (точный день% там не критичен).
   - Карточные/одиночные эндпоинты (`stockai/reco/dashboard/ai`, прайс-прокси) — оставить `yahoo()` (точность нужна, объём мал).
3. `liveMarkets` считать **один раз за вызов** и переиспользовать (после разнесения — в вызове максимум один анализ, так что один `liveMarkets`).

## B. Разнести задачи по вызовам (cron)
`scheduled` сейчас делает aiPortfolioRun + анализ ОБОИХ портфелей в одном вызове. Меняем на **одну задачу за тик** (каждый тик крона — отдельный вызов воркера со своим бюджетом):
- Рефактор: вынести `analyzeOnePortfolio(env, key, force, live)` (снапшот+anthropic+запись+Telegram для ОДНОГО портфеля; `live` — общий liveMarkets).
- В `scheduled` выбирать задачу по минуте (cron `*/10`): минуты 0/10 → `aiPortfolioRun`; 20/30 → анализ PF3 (Dima); 40/50 → анализ Anna. Гейты внутри (`intervalMin`, `pfAnalysisAt`) сохранить — они и так ограничивают реальные прогоны ~раз/час.
- Оценка после фикса (на вызов): aiPortfolioRun ≈26; analyzeOnePortfolio ≈33 — оба < 50. ✓

## C. Ручная кнопка `?action=aiport`
На free один вызов не вместит цикл + 2 анализа. Решение:
- `?action=aiport` → выполняет ТОЛЬКО цикл (`aiPortfolioRun`). Анализы реальных портфелей идут на cron (как в B).
- Добавить `?action=pfanalyze&key=<tab>` → ручной анализ ОДНОГО портфеля (отдельный вызов). Опционально подвязать к кнопке на сайте (мелкая правка `app*.js`, можно отдельной фазой).
- Клиент: кнопка «▶» продолжит работать (вернёт результат цикла); строку про анализ убрать/переориентировать.
