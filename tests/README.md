# Функциональные регрессионные тесты

Цель — при добавлении новых фич не ломать старые. Тесты гоняют **реальные
функции** из `app.js` и `telegram-notify.js` (а не их копии), поэтому ловят
регрессии в самой логике.

## Запуск

```bash
bash tests/run.sh
```

Выход `0` — всё зелёное; `1` — есть падения (или исходник не загрузился).
**Запускать перед каждым коммитом новой фичи.**

## Как устроено

Внешнего фреймворка/npm нет. Раннеры (`run-app.js`, `run-worker.js`) — это
скрипты для `osascript -l JavaScript` (движок JavaScriptCore):

1. поднимают минимальные заглушки браузерного окружения (`document`, `window`,
   `localStorage`, `fetch`, `crypto`, `supabase`, `ALL` …);
2. читают реальный исходник, убирают авто-`boot()` (app) / `export default`
   (worker);
3. `eval`-ят исходник вместе с кейсами в одном scope — кейсы видят настоящие
   функции и глобалы;
4. собирают результаты в `__res` и печатают сводку.

Кейсы — в `cases-app.js` и `cases-worker.js`.

## Что покрыто (сейчас)

- **Комиссия** (Avanza «Small»): `tradeFeeNative` / `tradeFeeNativeW` — паритет
  клиент↔воркер, минимум, FX-надбавка, UK stamp.
- **Валюта**: `pf3BaseFx` / `pf3Cv` / `pf3Money`.
- **Прогноз**: `pf3Fcast12` (по таргету и фундаменталу), `pf3FcTable`.
- **Таргеты**: `pf3EffTarget` / `pf3EffUpside`.
- **Раскладка-конструктор**: `eapply` (сохранение/новые/устаревшие id).
- **Сектора**: конфиг ETF, `sectPortfolioSet` (маппинг сектор→портфель).
- **Трек-рекорд**: `aiTrackRecord` (точность по вердиктам).
- **Журнал сделок**: `pfRecentTrades`.
- **Реко**: `pf3RecoHorizons.now` (валидный вердикт, не падает).
- **Синк**: `snapshotState` содержит все критичные пользовательские ключи
  (ловит «потерянный ключ» при правке синка — частая причина потери данных).
- **Worker**: `aiCost`, карта `MODELS`/`aiModel`, `round2`.

## Как добавить тест

В `cases-app.js` / `cases-worker.js` добавь группу:

```js
grp('моя фича', function(){
  __eq('что проверяю', myFunc(вход), ожидание);     // строгое равенство (JSON)
  __approx('число ~', myFunc(x), 16, 0.01);          // с допуском
  __ok('булево', condition);
});
```

Группа изолирована: исключение внутри `grp` не валит остальные тесты, а
отмечается как FAIL.

## Совет

При добавлении новой фичи с расчётами/состоянием — сразу пиши на неё кейс
(особенно если она пишет в синк: добавь ключ в проверку `snapshotState keys`).
